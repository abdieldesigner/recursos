--------------------------------------------------
Guardián de seguridad: body:has(.colores-abdiel, .colores-hub365)
--------------------------------------------------

Muchas reglas de color en abdiel-css.css (sección "colores personalizados")
empiezan con:

  body:has(.colores-abdiel, .colores-hub365) { ... }

Por qué existe:
abdiel-css.css es una librería GLOBAL que se carga automáticamente en
TODAS las páginas (nuevas y viejas). Cuando pasó a funcionar así, existía
el riesgo de que páginas viejas —que no tienen las variables CSS de
color bien configuradas— se rompieran visualmente al recibir estas
reglas de golpe. Por eso se agregó esta condición: las reglas de color
solo se activan si la página tiene la clase .colores-abdiel o
.colores-hub365 puesta a propósito en el body. Las páginas viejas sin
esa clase quedan protegidas/sin afectar.

Nota a futuro:
Si algún día TODAS las webs originales/viejas terminan siendo migradas
o actualizadas para tener las variables de color bien configuradas,
en ese punto SÍ se podría considerar eliminar esta condición de
seguridad (body:has(...)) de las reglas, ya que dejaría de ser
necesaria. Hasta entonces, debe mantenerse.

>>> ACTUALIZACIÓN 2026-11-23: EL GUARDIÁN YA FUE ELIMINADO <<<

Qué se hizo:
Se quitó el prefijo body:has(.colores-abdiel, .colores-hub365) de las 7
reglas de colores de abdiel-css.fuente.css. Las clases .colores-abdiel y
.colores-hub365 se dejaron como estaban, pero ya no son necesarias para
que esas reglas apliquen: ahora se aplican siempre, sin comprobar si la
clase existe.

Por qué:
- Rendimiento: body:has(...) obliga al navegador a mirar dentro de todo
  el body y a repetir la comprobación cada vez que cambia el DOM (GHL/Nuxt
  lo cambia mucho al cargar). Una de las reglas afectaba a todos los
  h1, h2, h3, h4 y p de la página.
- El guardián era un interruptor temporal mientras se migraban las webs.
  Ya pasó un año y la mayoría de las webs tienen las variables de color
  bien configuradas.

Cómo era el código antes (para volver a aplicarlo):
Cada regla empezaba con este prefijo, seguido de un espacio:

  body:has(.colores-abdiel, .colores-hub365)

Las 7 reglas afectadas (buscar en abdiel-css.fuente.css el comentario
"antes: body:has(.colores-abdiel, .colores-hub365)" o la nota
"2026-11-23"):
  1. .bg-degradado (y .faq-degradado ... .active)
  2. .cinta2 span, .cinta2 .marquee-text
  3. h1/h2 strong y .gradient-text / .text-degradado (texto con degradado)
  4. Esas mismas, en su versión ::before
  5. h1, h2, h3, h4, p, .button-icon-end ::before
  6. .boton-degradado, .btn-degradado
  7. .boton-degradado, .btn-degradado en :hover

Para volver atrás: poner de nuevo el prefijo delante del selector de cada
una de esas reglas y regenerar abdiel-css.css con
"node quitar-comentarios-css.js".

Cuidado (riesgo conocido):
- Una web que NO tenga definidas las variables --degradado-texto,
  --degradado-fondo o --degradado-boton ahora recibe esas reglas. Con
  --degradado-texto indefinido, el texto de h1/h2 strong,
  .text-degradado y .cinta2 puede quedar transparente (invisible), porque
  la regla pone -webkit-text-fill-color: transparent.
- Al quitar body:has(...) baja la especificidad de esas reglas (de
  0,1,1 a 0,1,0 o similar). Alguna regla de la web podría ahora ganarles.

--------------------------------------------------
Carrusel con scroll-pin (avanza solo con el scroll de la página)
--------------------------------------------------

Qué hace:
Convierte el scroll vertical normal de la página en el movimiento
horizontal de un carrusel — mientras se scrollea esa sección, el
carrusel se desliza solo, sin que el usuario arrastre ni toque flechas.

Clases necesarias (van en DOS elementos distintos, no en el mismo):

1. En la SECCIÓN de GHL que envuelve todo (título, texto, carrusel):
     section-scroll-pin
   Esta es la clase que el JS busca para activar el efecto:
     document.querySelectorAll('.section-scroll-pin').forEach(...)
   Si falta aquí, el efecto NUNCA se activa — aunque el carrusel
   adentro tenga bien puesta su propia clase.

2. En el carrusel mismo (el contenedor .card-carrusel):
     scroll-pin
   Opcional: agregar también "scroll-pin-paso" para que las tarjetas
   avancen de una en una (con salto) en vez de deslizarse continuo.

Error común (ya visto en una página real):
Poner "scroll-pin" solo en el carrusel y olvidar "section-scroll-pin"
en la Sección. Resultado: el carrusel funciona normal (flechas, swipe),
porque ese es otro script aparte que solo necesita .card-carrusel, pero
el scroll-pin nunca arranca porque el JS no encuentra ninguna sección
con la clase que busca.

Dónde está el código:
abdiel-css.css → sección "INICIA CSS: scroll-pin carrusel"
abdiel-js.js   → sección "INICIA JS: scroll-pin carrusel"

--------------------------------------------------
No indexar sitios de prueba (noindex)
--------------------------------------------------

Para cuando un sitio completo todavía está en etapa de prueba (dominio
de test, nada definitivo todavía): va en el head GLOBAL del sitio
(nunca en abdiel-css.css/abdiel-js.js, es código de página, no CSS/JS).

<!-- TEMPORAL: sitio de prueba — eliminar esta línea cuando pase al dominio definitivo y se haga público -->
<meta name="robots" content="noindex, nofollow">

Si en cambio es solo una o varias páginas sueltas de prueba (Test, etc.)
dentro de un sitio que ya es público, la misma línea va en el head
INDIVIDUAL de cada una de esas páginas, no en el global — si se pone
en el global ahí sí desindexa el sitio entero por error.

Al pasar al dominio definitivo y hacerlo público: borrar esa línea
(del head global o de cada página, según cuál se haya usado) y
cambiar el dominio.

--------------------------------------------------
2026-11-23: CSS del calendario (.nr-*) retirado de la librería
--------------------------------------------------

Qué se hizo:
El bloque "CSS Calendario" (clases .nr-wrap, .nr-chip, .nr-month, .nr-modal,
.nr-btn, #nr-chips, etc.) quedó comentado en abdiel-css.fuente.css (buscar
"DESACTIVADO 2026-11-23: CSS del calendario"). Como la versión en vivo
(abdiel-css.css) se genera sin comentarios, ese CSS ya no se descarga en las
webs (~3,5 KB menos).

Por qué es seguro:
Extras/Calendario Google o manual .html ya trae el CSS completo del
calendario dentro de su propio <style>, así que funciona sin la librería.
Se usa siempre pegando ese archivo completo (HTML + CSS).

Cuidado:
- Una web que tenga solo el HTML del calendario, sin el <style> del archivo
  de Extras, perdería los estilos. Para volver atrás: quitar el comentario
  en abdiel-css.fuente.css y regenerar con "node quitar-comentarios-css.js".
- El bloque definía en :root las variables globales --accent1, --accent2,
  --ink y --muted (la librería con --accent1 dorado #e3c35b; el archivo de
  Extras con --accent1 morado #8e73c2). Ya no se definen globalmente: solo
  existen cuando se pega el archivo de Extras.
- El bloque "Variebles de calendario" (widget nativo de citas de GHL,
  .appointment_widgets--revamp--container) NO se tocó.
